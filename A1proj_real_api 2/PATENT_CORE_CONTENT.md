# 多模态六阶段检索增强生成流水线 — 专利申请核心内容

---

## 一、技术领域

本发明属于计算机数据处理技术领域，具体涉及一种面向工业设备故障诊断的多模态检索增强生成（Retrieval-Augmented Generation，RAG）方法及系统，由计算机设备作为统一执行主体完成从多源异构文档解析、知识抽取与建库、多模态查询解析、多阶段检索融合到诊断报告生成的完整数据处理流程。

### 附图2：检索阶段六阶段流水线流程图

附图2为本发明实施例提供的六阶段检索增强生成流水线的详细处理流程图。该流程图以计算机设备为执行主体，展示如下步骤：

步骤S201（视觉增强阶段）：计算机设备接收用户输入的文本查询字符串和可选的故障图像数据，调用多模态视觉大模型（Vision Large Language Model，VLM）对故障图像进行结构化分析，提取故障代码、故障描述和关键词列表，将提取的结构化字段注入检索查询字符串，生成增强查询字符串。

步骤S202（向量检索阶段）：计算机设备将增强查询字符串发送至云端向量嵌入服务，获取查询向量，在云端向量数据库中执行近似最近邻（Approximate Nearest Neighbor，ANN）检索，返回语义相似度最高的前2K条知识文档。

步骤S203（关键词检索阶段）：计算机设备对增强查询字符串执行中文分词和二元组（bigram）切分，在全量知识文档集中进行关键词精确匹配扫描，计算每个匹配文档的关键词得分，并对包含完整查询短语的文档给予精确匹配加成。

步骤S204（代码提取阶段）：计算机设备对增强查询字符串执行正则表达式匹配，提取符合数控报警代码格式的数字代码和英文报警短语，在报警代码表文档中进行精确定位扫描，对匹配到的文档给予代码精确匹配加权，并过滤未出现在报警上下文窗口内的误匹配文档。

步骤S205（多路合并与报警代码增强阶段）：计算机设备将步骤S202、S203、S204的三路检索结果按加权公式进行第一轮合并，然后对合并结果中包含报警代码表的文档执行代码精确匹配验证，对验证通过的文档给予额外加权。

步骤S206（图谱扩展阶段）：计算机设备从第一轮合并结果的排序前3条文档中提取文档标识符，在知识图谱中沿实体关系边进行邻居扩散查找，发现与种子文档共享标签节点、部件节点或故障节点的关联文档，对关联文档赋予图谱增强权重。

步骤S207（第二轮合并）：计算机设备将图谱扩展阶段返回的关联文档与第一轮合并结果按同一加权公式进行第二轮合并，输出最终排序的前K条检索结果文档。

步骤S301（上下文构建与生成）：计算机设备将最终检索结果拼接为诊断上下文文本块，注入预设的诊断系统提示模板，构建完整提示词，调用大语言模型生成故障诊断报告。

附图3为本发明实施例中多路检索结果加权融合计算公式的参数关系示意图。该图以树状结构展示合并得分S的计算过程：根节点为合并得分S，其下分出三个加权子项——关键词得分项（权重α=0.45）、向量得分项（权重β=0.45）和图谱增强项（权重γ=0.10）。关键词得分项连接至归一化关键词得分Kw（由文档原始关键词得分除以当前批次最大关键词得分得到），向量得分项连接至向量相似度得分Vv（由向量数据库直接返回的相似度分值），图谱增强项连接至图谱增强权重Gb（由知识图谱扩展阶段赋予的固定增强值或零值）。每个子项的输入参数旁标注该参数的数据来源：Kw来源于关键词检索阶段模块（203），Vv来源于向量检索阶段模块（202），Gb来源于图谱扩展阶段模块（206）。

## 三、发明内容

### 3.1 所要解决的技术问题

现有数控机床故障诊断领域中的检索增强生成方案存在以下技术问题：

（1）报警代码检索失准：数控系统报警代码为纯数字字符串（如"176"、"HM31"等），在基于语义嵌入的向量检索中，此类数字字符串被当作普通词元（token）进行向量化，导致数值参数（如"主轴转速176rpm"中的"176"）与报警代码（如"176号报警"中的"176"）在向量空间中距离相近，向量检索无法区分其语义差异，检索精度低。

（2）多模态信息割裂：现有方案将故障图像经视觉模型转换为自由文本描述后，直接与用户文本查询拼接送入纯文本检索流水线，视觉分析产生的结构化信息（报警代码、关键词、故障部位）在转换过程中被压平为无结构自由文本，丧失了代码的精确匹配属性和关键词的独立权重信息。

（3）文档孤岛效应：维修知识库中文档以独立分块形式存储，不同章节之间的因果关联（如"主轴过载报警"与"伺服参数设置"之间的因果关系）无法被向量检索或关键词检索发现，检索结果仅包含与查询语义最相似的分块，缺失跨文档因果链。

（4）本地计算依赖与国产平台适配障碍：现有方案依赖本地FAISS（Facebook AI Similarity Search，Facebook人工智能相似性搜索库）向量索引和本地GPU（Graphics Processing Unit，图形处理器）模型推理，在龙芯LoongArch等国产处理器指令集架构平台上，因缺乏预编译二进制发行包和GPU硬件支持而无法部署。

### 3.2 技术方案

本发明提供一种多模态六阶段检索增强生成方法，由计算机设备作为统一执行主体完成全部数据处理流程。所述方法包括离线知识构建阶段和在线检索生成阶段。

#### 3.2.1 离线知识构建阶段

计算机设备执行以下步骤，构建结构化知识库、知识图谱和向量索引：

**步骤A1（文档解析与分块）：** 计算机设备扫描预设数据目录，获取数控机床维修手册文件，所述维修手册文件包括便携式文档格式（Portable Document Format，PDF）文件、办公文档开放XML格式（Office Open XML，DOCX）文件和电子表格格式（Microsoft Excel，XLS/XLSX）文件。对于PDF文件，计算机设备调用文本提取接口提取文本内容，若检测到平均每页字符数低于预设阈值（100字符/页），则判定为扫描版PDF，自动触发光学字符识别（Optical Character Recognition，OCR）引擎进行图像转文本处理。对于XLS/XLSX文件，计算机设备按行读取报警代码列、名称列、解析列和解决方法列，逐行生成结构化知识条目，每个知识条目的内容字段以固定格式标注"报警代码：{代码}"以支持后续精确定位。计算机设备按预设分块大小（900字符）和重叠窗口（120字符）对长文本进行滑动窗口切割，为每个分块生成唯一文档标识符，所述文档标识符由源文件名、序号和标题摘要拼接而成。

**步骤A2（三元组抽取）：** 计算机设备将步骤A1生成的知识文档分批送入大语言模型，调用三元组抽取提示模板指示大语言模型从文档文本中提取实体-关系-实体三元组。每条三元组由头实体类型、头实体名称、关系、尾实体类型、尾实体名称五部分组成，实体类型限定为：设备（device）、部件（component）、故障（fault）、故障原因（fault_cause）和解决方案（solution）五种。大语言模型以每行一条三元组的固定格式输出，每批次处理不超过5条文档。

**步骤A3（三元组校验）：** 计算机设备逐条解析大语言模型输出的三元组，执行三项校验——实体类型合法性校验（头实体类型和尾实体类型必须属于预设的合法实体类型集合）、实体名称非空校验、关系长度区间校验（关系字符串长度介于2至80字符之间）。计算机设备同时对实体名称执行清洗：将全角括号替换为半角括号、将中文逗号替换为英文逗号、合并连续空格。校验不通过的三元组被丢弃并记录错误日志，校验通过的三元组进入下一步骤。

**步骤A4（三元组消重）：** 计算机设备对校验通过的三元组集合执行两阶段消重处理。第一阶段为实体名称归一化：以（实体类型，实体名称）二元组为键建立映射表，后续出现的同类型同名实体统一采用首次出现的实体名称。第二阶段为三元组去重：以完整五元组（头实体类型，头实体名称，关系，尾实体类型，尾实体名称）为键建立去重集合，剔除完全重复的三元组。

**步骤A5（关系数据库写入）：** 计算机设备将消重后的三元组写入关系数据库。对于每条三元组的头实体和尾实体，计算机设备按实体类型路由至对应的数据库表（设备表、部件表、故障表、故障原因表、解决方案表），执行"查询已有记录→存在则复用、不存在则新建"的幂等插入操作；随后在关系表中写入一条关系记录，该关系记录包含头实体类型、头实体业务标识符、关系类型、尾实体类型、尾实体业务标识符、置信度和来源文档字段。

**步骤A6（知识图谱构建）：** 计算机设备读取全部知识文档，为每个文档创建文档节点，并从文档文本中按预设规则提取标签节点、部件节点、故障节点和设备型号节点。提取规则包括：从文档标签字段中提取标注边、从预设部件词表中匹配部件边、从预设故障模式正则表达式中匹配故障边。计算机设备按每文档每类边不超过1条的上限控制图谱密度，最终输出包含节点列表和边列表的知识图谱JSON（JavaScript Object Notation，JavaScript对象表示法）文件。

**步骤A7（云端向量索引构建）：** 计算机设备将全部知识文档的文本内容（标题与正文拼接）通过云端文本嵌入应用程序接口（Application Programming Interface，API）转换为稠密向量，批量写入云端向量数据库的指定集合中。所述云端文本嵌入API和云端向量数据库均部署于云服务平台，计算机设备通过超文本传输协议（Hypertext Transfer Protocol，HTTP）与云端服务通信，本步骤不依赖任何本地C/C++编译库或GPU硬件。

其技术作用在于：S201中视觉分析结果以结构化字段（故障代码、故障描述、关键词列表）的形式保留并注入增强查询字符串，而非压平为自由文本，使得故障代码字段可被后续代码提取阶段精确匹配利用；S205中对报警代码表来源文档进行二次精确匹配验证并给予+15的额外加权，确保当用户查询或故障图像中包含明确报警代码时，对应的报警代码解析文档在最终排序中具有绝对优先级。解决了现有方案中数字报警代码被向量语义噪声淹没的技术问题。

**阶段二：向量检索阶段。** 计算机设备在接收所述增强查询字符串后，执行以下子步骤：

（a）计算机设备将所述增强查询字符串发送至云端文本嵌入API，所述云端文本嵌入API采用DashScope兼容嵌入模型（DashScope-Compatible Embedding Model），以原始文本字符串（而非经分词器预处理的整数序列）作为输入，通过HTTP POST请求获取对应的高维嵌入向量（Embedding Vector），嵌入维度为1024维；

（b）计算机设备将所述高维嵌入向量作为查询向量，在云端向量数据库DashVector中执行近似最近邻检索，返回与所述查询向量余弦相似度最高的前2K条文档，K为预设的最终返回文档数；每条返回文档携带由向量数据库直接给出的向量相似度得分Vv。

其技术作用在于：云端向量检索替代本地FAISS索引，消除了C++编译依赖和GPU硬件依赖，使本方法可在龙芯LoongArch等国产处理器平台上部署运行。

**阶段三：关键词检索阶段。** 计算机设备在接收所述增强查询字符串后，执行以下子步骤：

（a）计算机设备对所述增强查询字符串进行分词处理，提取中文词语片段（Unicode范围U+4E00至U+9FFF的连续字符序列）和英文/数字片段（ASCII字母和数字的连续字符序列），同时以滑动窗口步长1生成二元组（bigram）序列；

（b）计算机设备遍历全量知识文档集，对每个知识文档计算关键词得分，所述关键词得分为该文档文本中包含的上述分词片段和二元组的总数量；

（c）若所述增强查询字符串整体作为连续子串出现在文档文本中，计算机设备对该文档的关键词得分增加精确短语匹配加成值Pu=5.0；

（d）若文档文本中连续匹配的二元组数量达到或超过3个，计算机设备对该文档的关键词得分增加连续匹配加成值Pc=2.0；

（e）计算机设备读取视觉增强阶段输出的关键词列表，若关键词列表非空，从中筛选代码类关键词（包含ASCII字母或数字的关键词），以筛选后的代码类关键词拼接为补充查询字符串，在知识文档集中执行第二轮关键词检索，将新增的匹配结果合并入关键词检索结果集；

（f）计算机设备按关键词得分降序排列，返回前2K条文档。

其技术作用在于：中文分词与二元组的双重匹配机制同时覆盖单字词匹配和短语匹配，精确短语匹配加成弥补了分词粒度不匹配导致的长短语无法命中问题。

**阶段四：代码提取阶段。** 计算机设备在接收所述增强查询字符串后，执行以下子步骤：

（a）计算机设备对增强查询字符串执行正则表达式匹配，提取两类代码模式：第一类为数字报警代码——长度2至4位、前后无字母数字下划线连接的孤立数字串，匹配模式为"(?<![a-zA-Z0-9_])\d{2,4}(?![a-zA-Z0-9_])"；第二类为英文报警短语——由3个及以上大写英文字母组成的连续大写英文短语，匹配模式为"[A-Z][A-Z\s]{3,}[A-Z]"；

（b）若未提取到任何代码模式，本阶段直接返回空结果集，结束阶段四；

（c）若提取到代码模式，计算机设备将提取到的数字报警代码和英文报警短语拼接为代码查询字符串，并追加报警上下文关键词（从"报警、故障、代码、错误、异常、停机、返回、参考、急停、过热、过载"中匹配增强查询字符串中出现的词），在知识文档集中执行关键词检索；

（d）计算机设备单独扫描报警代码表来源的XLS/XLSX文档，对每个提取到的数字报警代码，检查文档内容中是否存在"报警代码：{代码}"或"报警 {代码}"格式的文本，若存在，将该文档以高关键词得分值Cb=50插入代码检索结果集的头部位置；

（e）计算机设备对代码检索结果集执行报警上下文过滤：对于每条候选文档，检查文档文本中代码出现位置的±80字符窗口内是否包含报警上下文关键词正则表达式（匹配"报警|故障|错误|异常|代码|停机"），排除未出现在报警上下文窗口内的误匹配文档；通过过滤的文档获得代码精确匹配加成值Cm=8。

其技术作用在于：通过正则表达式精确提取数字报警代码并单独扫描报警代码表文档、再以报警上下文窗口过滤噪声匹配，将报警代码检索从模糊语义匹配升格为结构化精确匹配，从根本上解决了现有技术中数字报警代码与数值参数在向量空间中无法区分的技术问题。

**阶段五：多路合并与报警代码增强阶段。** 计算机设备执行以下子步骤：

（a）第一轮合并：计算机设备将关键词检索阶段返回的结果集R_kw、向量检索阶段返回的结果集R_vec和代码提取阶段返回的结果集R_code按文档标识符（若文档标识符为空则以文档标题替代）进行去重合并。合并规则为：同一文档在多路结果集中出现时，取各路分数的最大值分别作为该文档的关键词得分K_raw和向量得分V_raw；

（b）加权融合：计算机设备按以下加权融合公式计算每个合并文档的合并得分S：

```
S = α × Kw + β × Vv + γ × Gb
```

其中：
α = 0.45，为关键词权重系数；
Kw = K_raw / K_max，为归一化关键词得分，K_raw为文档原始关键词得分，K_max为当前合并结果集中所有文档原始关键词得分的最大值；
β = 0.45，为向量权重系数；
Vv = V_raw，为向量相似度得分，由向量检索阶段直接返回；
γ = 0.10，为图谱增强权重系数；
Gb为图谱增强值，在第一轮合并时取0，在第二轮合并时由图谱扩展阶段赋予；

计算机设备按合并得分S降序排列，取前2K条文档作为第一轮合并结果。

（c）报警代码增强：计算机设备检查视觉增强阶段输出的视觉分析结果中关键词列表是否非空，若为空则跳过本子步骤直接返回第一轮合并结果。若关键词列表非空，计算机设备从文本查询字符串和增强查询字符串中按正则表达式提取数字报警代码，遍历第一轮合并结果中的每条文档，对于来源为报警代码表的文档，检查文档内容中是否存在"报警代码：{代码}"或"报警 {代码}"格式的文本，若存在，则对该文档的关键词得分增加报警代码增强加成值Ca=15。增强后的文档重新参与加权融合公式计算，更新合并得分S和排序。

其技术作用在于：当故障图像中包含明确报警代码时，报警代码增强加成为报警代码表来源的文档赋予显著权重优势（额外+15），确保报警代码对应的官方解析文档在最终检索排序中始终位于前列，解决了现有方案中报警代码表文档被大篇幅维修手册文本通过语义相似度"淹没"的问题。

**阶段六：图谱扩展阶段。** 计算机设备执行以下子步骤：

（a）计算机设备从第一轮合并结果的排序前3条文档中提取文档标识符列表作为种子节点集合；

（b）计算机设备加载离线构建阶段生成的知识图谱，在知识图谱的边集合中遍历查找源节点或目标节点属于种子节点集合的边，获取与种子节点直连的邻居节点；

（c）对于每个邻居节点，若其节点类型为标签（tag）、部件（component）、故障（fault）或设备型号（device_model）类型，则进一步查找与该邻居节点相连的其他文档节点；

（d）将查找到的其他文档节点的文档标识符与种子节点集合做差集运算，排除已在前序阶段出现过的文档，得到扩展文档标识符集合；

（e）从全量知识文档集中按扩展文档标识符集合检索对应的完整文档数据，为每条扩展文档赋予固定的图谱增强值Gb=0.6；

（f）扩展文档数量上限为5条，达到上限后停止图谱遍历。

其技术作用在于：利用知识图谱中实体之间的因果关系边和分类关系边，从语义检索返回的种子文档出发，自动发现与之存在因果关联或分类关联的其他文档（例如从"主轴过载报警"文档通过共享的"主轴"部件节点发现"伺服参数设置"文档），弥补了向量检索和关键词检索均无法跨越文档分块边界发现因果链信息的技术缺陷，解决了文档孤岛效应问题。

**步骤S207（第二轮合并）：** 计算机设备将图谱扩展阶段返回的扩展文档集合与步骤S205的第一轮合并结果按步骤S205子步骤（b）中所述同一加权融合公式进行第二轮合并计算，此时公式中的图谱增强值Gb取图谱扩展阶段赋予的固定值0.6（对于非扩展文档Gb=0）。计算机设备按合并得分S降序排列，取前K条文档作为最终检索结果。

**步骤S301（上下文构建与报告生成）：** 计算机设备执行以下子步骤：

（a）计算机设备遍历最终检索结果中的每条文档，对文档内容执行非中英文字符清洗（保留中文Unicode区块U+4E00-9FFF和U+3000-303F、ASCII字母数字和空白字符），并为每条文档标注匹配度等级（得分S>0.4标注四星、得分S>0.25标注三星、其余标注二星）和诊断字段标记（根据文档内容中出现的预设诊断标记词自动标注对应的图标标记）；

（b）计算机设备将所有文档以固定分隔符拼接为诊断上下文文本块，总长度不超过3000字符；

（c）计算机设备将诊断上下文文本块注入预设的诊断系统提示模板，构建包含系统角色设定字段和知识库检索结果字段的结构化提示词；

（d）计算机设备将所述结构化提示词发送至云端大语言模型API，调用大语言模型生成包含故障诊断、原因分析、解决方案和经验总结四个固定板块的故障诊断报告。

## 四、技术效果

本发明提供的多模态六阶段检索增强生成方法相比现有技术具有以下有益效果：

（1）报警代码检索精度显著提升：通过将报警代码精确匹配（代码提取阶段+报警代码增强阶段）独立于语义向量检索，并在加权融合公式中赋予关键词路径45%的权重占比，确保数字报警代码的检索结果不被语义噪声淹没。报警代码表文档在包含明确代码的查询中始终获得最高排序优先级。

（2）多模态信息无损传递：视觉增强阶段输出的结构化字段（故障代码、关键词列表）以独立数据结构注入后续阶段参与精确匹配，而非被压平为自由文本后仅参与向量语义匹配，充分利用了图片中的报警信息。

（3）跨文档因果链发现：通过知识图谱边扩散机制，自动从语义相关文档出发发现因果关联文档，弥补了传统单路检索的文档孤岛缺陷。

（4）国产平台可部署：以云端向量数据库替代本地FAISS、以云端API替代本地模型推理和本地文本嵌入，使整个流水线无C++编译依赖、无GPU硬件依赖，可在龙芯LoongArch指令集架构等国产处理器平台上仅通过Python运行时环境和HTTP网络通信完成全部数据处理流程。
